# UI-автотесты Practice Automation

Решение задания полуфинала «Автоматизация тестирования (Java, Python)».
Python 3.12+, Selenium 4, Pytest, Page Object Model, Allure.
31 сценарий: на каждой из трёх обязательных страниц по 7 позитивных и 3 негативных; отдельный сценарий проверяет требование Message на странице Form Fields.

## Установка и запуск

Установите Python 3.12+ и актуальный Chrome либо Firefox. Отключите блокировщики рекламы. Из каталога проекта:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

```bash
python -m pip install -r requirements.txt
python -m pytest
python -m pytest --browser=firefox
python -m pytest --browser=chrome --headed
```

Selenium Manager автоматически подбирает драйвер. При первом запуске нужен доступ к серверам загрузки драйверов и браузеров. Для уже установленного драйвера задайте `DRIVER_PATH`, для нестандартного расположения браузера — `BROWSER_BINARY`.

```bash
python -m pytest -m positive
python -m pytest -m negative
python -m pytest tests/test_calendars.py
python -m pytest --timeout=30 --base-url=https://practice-automation.com
```

`--container` — дополнительный режим Chrome для запуска в изолированном Linux-контейнере (без browser sandbox, с обходом малого /dev/shm). Для обычного компьютера не нужен.

Каждый тест получает отдельный браузер: состояние, cookies и заполненные формы не передаются между сценариями. Используются явные ожидания, без `time.sleep` и без повторных запусков, маскирующих ошибки.

## Allure

Установите Allure CLI и Java согласно инструкции выбранного дистрибутива Allure. Python-плагин устанавливается из requirements.txt. Все запуски автоматически пишут результаты в `allure-results`.

Перед новым независимым прогоном удалите старый каталог `allure-results`, чтобы отчёт не смешивал разные запуски.

```bash
python -m pytest
allure serve allure-results
```

Либо сформируйте постоянный HTML-отчёт:

```bash
allure generate allure-results --clean -o allure-report
allure open allure-report
```

Отчёт содержит названия сценариев, параметры, шаги, статусы и окружение. При ошибке после создания браузера прикладываются скриншот PNG, URL и HTML. Если браузер не создался, скриншот получить невозможно — причина будет в traceback фикстуры. Готовый успешный отчёт не подменяется заранее сгенерированными результатами.

## Анализ страниц и допущения

- Calendars: текстовое поле даты формата YYYY-MM-DD, выбор дня и переход между месяцами. В текущем JavaScript сайта используется Jetpack date picker (`.dp`, `.dp-next`, `.dp-prev`), а не jQuery UI. Выбор выполняется кликами по календарю, без подмены значения JavaScript.
- Modals: простое информационное окно и окно с контактной формой. Имя обязательно, email необязателен, но при заполнении должен быть корректным. Message заполняется названиями инструментов через запятую. Простое окно не закрывается Escape; форма закрывается Escape — это соответствует конфигурации Popup Maker в приложенных HTML.
- Ads: рекламное окно автоматически открывается примерно через 4,5 секунды плюс анимация. Закрывается крестиком; Escape и нажатие на подложку отключены в конфигурации. Тесты не требуют точного времени открытия из-за сетевой задержки.
- Негативные проверки рекламы означают запрещённые способы закрытия и взаимодействия с фоном: у рекламы нет полей для некорректного ввода.
- Источник списка инструментов — раздел Automation tools на `/form-fields/`, список `li`, следующий за соответствующим label. Названия не захардкожены: Selenium читает DOM, Python соединяет их через `', '.join(...)`, Selenium вводит результат в Message. Дополнительный FORM-P01 проверяет исходную страницу; MOD-P07 применяет тот же список к модальной форме.
- Отправка корректной модальной формы выполняет реальный запрос к учебному сайту. Используются тестовое имя и email домена example.com. Антиспам, недоступность сервера и изменение интерфейса могут привести к падению: тесты это показывают, а не пропускают.
- Некорректная дата должна приводить к видимой ошибке валидации. Если сайт принимает невозможную дату, тест фиксирует дефект, а не объявляет его ожидаемым успехом. Пустая дата не объявлена обязательной, поэтому её запрет не выдумывается.
- Сохранённые HTML не содержат папок внешних ресурсов и не заменяют работающий сайт; запуск через file:// не поддерживается.

## Тестовые сценарии

Общие предусловия: новая сессия браузера, открыта указанная страница, JavaScript включён, блокировщики отключены. Полный сценарий каждой строки — общие предусловия + шаги строки + ожидаемый результат. Для ввода в форму Message всегда получается из реального списка Automation tools.

## Структура

- `pages/ui.py` — Page Object классы Page, Calendar, Modals, Ads; локаторы и операции.
- `tests/` — проверки результата и параметры сценариев.
- `conftest.py` — настройки запуска, независимые браузеры, диагностика Allure.
- `requirements.txt`, `pytest.ini` — зависимости и настройки.

## Что проверено при подготовке

Проверены компиляция Python-модулей и сборка Pytest: обнаружен 31 тест. Локаторы календаря сверены с текущим JavaScript Jetpack; локатор списка инструментов — с HTML Form Fields; конфигурация закрытия окон — с приложенными HTML.

Полноценный UI-прогон не подтверждён: в среде подготовки Chrome завершился до создания сессии с `socket() failed: Operation not permitted`. После повторной попытки с `--container` ограничение сохранилось. Это ошибка окружения, а не результат проверок сайта. Реальный Allure-отчёт следует получить после запуска на компьютере с работающим Chrome/Firefox. Результаты неуспешных попыток запуска окружения в архив не включены.
